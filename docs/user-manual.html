社區出入管理系統 使用說明書

適用版本：單機版（uv run gate serve）與容器版（Docker）

讀者：第一篇給 IT／安裝人員，第二篇給警衛與管理員。

系統簡介

本系統是給社區警衛室使用的出入管理工具，透過攝影機辨識車牌，自動判斷車輛能否進出：

車輛身分 系統動作
住戶白名單車輛（在有效期內） 自動開閘
已登記訪客（在授權時段內） 自動開閘，並記錄入場／離場
黑名單車輛 拒絕，發出黑名單警示
未登記車輛 跳出「待確認」視窗，由警衛決定：放行一次／登記為訪客／拒絕

每筆進出都會留下紀錄與現場截圖，可依條件查詢並匯出 Excel 或 CSV。

第一篇　安裝與部署

1. 系統需求

項目 需求
作業系統 macOS、Linux、Windows（可執行 Python 3.12 即可）
Python 3.12，建議用 uv 管理
Node.js 只有修改前端（frontend/）時才需要；backend/app/static/ 已附建置好的畫面
網路 首次辨識車牌需連網下載辨識模型（約數十 MB），之後可完全離線
攝影機 RTSP 網路攝影機、USB 攝影機，或用手機當攝影機（測試用）
柵欄 可先用「模擬柵欄」；正式現場接 HTTP 繼電器（ESP32／Shelly）或 Modbus TCP 繼電器

2. 安裝與第一次啟動

在專案根目錄執行：

# 1. 安裝後端套件（含車牌辨識用的 ONNX Runtime）
uv sync

# 2. 建立第一組登入帳號（會互動詢問帳號、密碼）
uv run gate create-admin

# 3. 啟動伺服器
uv run gate serve

啟動後用瀏覽器開啟 http://127.0.0.1:8000，以剛建立的帳號登入。

注意：資料預設存在專案下的 data/ 目錄（SQLite 資料庫 data/app.db、Session 金鑰、HTTPS 憑證）。請勿刪除此目錄，並定期備份（見第 6 節）。

若要使用 Modbus TCP 繼電器，需額外安裝套件：

uv sync --extra modbus

3. 啟動選項（區網、HTTPS）

uv run gate serve 的參數：

參數 說明
--host 監聽位址。預設 127.0.0.1（只有本機可連）；要讓區網其他電腦或手機連線，改成 0.0.0.0
--port 埠號，預設 8000
--ssl 啟用 HTTPS。手機瀏覽器必須在 HTTPS 下才能開相機，用手機當攝影機時一定要加
--ssl-cert / --ssl-key 使用自備憑證；未指定時系統會在 data/ 自動產生自簽憑證

常見組合：

# 只在警衛室這台電腦使用
uv run gate serve

# 區網內多台電腦／手機要連線，且要用手機鏡頭
uv run gate serve --host 0.0.0.0 --port 8000 --ssl

使用自簽憑證時，瀏覽器會顯示「不安全／非私人連線」，請點「進階」→「繼續前往」。

4. 設定車道、攝影機與柵欄

登入後進入 系統設定 → 車道與硬體，按 新增車道。

4.1 車道欄位

欄位 說明
車道名稱 例：大門入口、機車出口
方向 進場 或 離場。影響訪客入場／離場狀態與在場車輛統計
車道車種 汽機車皆可／汽車專用／機車專用。專用車道辨識到的車輛會直接標記該車種
攝影機來源 見 4.2
柵欄驅動 模擬柵欄／HTTP 繼電器／Modbus TCP 繼電器，見 4.3
驅動參數 (JSON) 選擇實體繼電器時填寫
未知車自動放行 開啟後，未登記車輛不跳視窗、直接開閘。建議只在出口車道開啟
啟用車道 關閉後該車道停止擷取影像

4.2 攝影機來源格式

來源 填寫範例
RTSP 網路攝影機（正式現場） rtsp://帳號:密碼@192.168.1.20:554/stream1
USB 攝影機 0（第一支）、1（第二支）
Android「IP Webcam」App http://手機IP:8080/video
iPhone「DroidCam」App http://手機IP:4747/video
測試影片 影片檔的本機路徑
手機瀏覽器（免裝 App） 不用填，改用「📱 手機鏡頭」QR Code，見 4.4

第三方 IP Cam App 是由伺服器主動去拉影像，只有伺服器跟手機在同一個區網時才能用；雲端部署請改用 QR Code 方式。

架設建議：台灣機車車牌小且位於車尾，機車道攝影機請低角度、近距離拍車尾。

4.3 柵欄驅動與參數

模擬柵欄：不需參數，只在畫面上顯示開閘，適合測試或雲端展示。

HTTP 繼電器（ESP32 自製韌體、Shelly 等）：

{
  "url": "http://192.168.1.50/relay/0?turn=on&timer=2",
  "method": "GET",
  "timeout": 3,
  "health_url": "http://192.168.1.50/status"
}
參數 必填 說明
url 是 觸發開閘的網址
method 否 HTTP 方法，預設 GET
timeout 否 逾時秒數，預設 3
health_url 否 健康檢查網址
headers 否 額外 HTTP 標頭（例如驗證金鑰）

Modbus TCP 繼電器（需先 uv sync --extra modbus）：

{ "host": "192.168.1.60", "port": 502, "unit": 1, "coil": 0, "pulse_sec": 1.0 }

系統以「coil 寫入 ON → 等待 pulse_sec 秒 → 寫入 OFF」的脈衝方式觸發柵欄。

設定完成後，在車道列表按 測試開閘 確認柵欄有動作。開閘失敗時會在警示中心產生「柵欄異常」警示。

4.4 用手機當攝影機（QR Code）

  1. 用 --host 0.0.0.0 --ssl 啟動伺服器。
  2. 電腦瀏覽器用區網 IP 開啟系統（例：https://192.168.x.x:8000）。
  3. 在 即時監控 的車道卡片，或 系統設定 → 車道與硬體 點 📱 手機鏡頭，畫面會顯示 QR Code。
  4. 手機相機掃描 QR Code，若出現不安全提示選「進階 → 繼續前往」，再允許相機權限。
  5. 手機畫面即成為該車道的辨識攝影機。下方工具列可切換 前／後鏡頭、開關 補光燈；辨識到車牌時會跳出結果卡片。

5. Docker／雲端部署

完整說明見 deployment.md，以下為重點。

docker build -t community-gate:local .

docker run --rm -p 8000:8000 \
  -v "$(pwd)/data:/app/data" \
  -e GATE_ADMIN_USERNAME=admin \
  -e GATE_ADMIN_PASSWORD=<至少6碼的密碼> \
  community-gate:local

常用環境變數：

變數 說明
DATABASE_URL 外部 MySQL 8.4 連線字串；未設定則使用 SQLite
GATE_ADMIN_USERNAME / GATE_ADMIN_PASSWORD 首次啟動時自動建立的管理帳號
GATE_SECRET_KEY Session 金鑰。雲端務必設定，否則每次重啟所有人都會被登出
GATE_SESSION_MAX_AGE_SEC 登入有效秒數，預設 43200（12 小時）
GATE_DATA_DIR 資料目錄，預設 ./data

實體繼電器通常位於社區內網，正式現場請使用警衛室單機版；雲端版建議搭配模擬柵欄做展示或遠端測試。

6. 備份、帳號維護與 CLI 指令

指令 用途
uv run gate create-admin 新增登入帳號（可加 -u 帳號 -n 顯示名稱）
uv run gate reset-password <帳號> 重設密碼（忘記密碼、無法登入時使用）
uv run gate backup 備份 data/app.db 為 data/backup_*.db（可加 -o 路徑）
uv run gate serve 啟動伺服器（參數見第 3 節）

備份建議：每日以排程執行 uv run gate backup，並把備份檔複製到另一顆硬碟或雲端。備份只涵蓋 SQLite；使用 MySQL 時請以資料庫本身的備份機制處理。

第二篇　日常操作

7. 登入與畫面導覽

  1. 開啟系統網址，輸入帳號、密碼登入。帳號由管理員在「系統設定 → 操作員帳號」建立。
  2. 登入有效 12 小時，逾時需重新登入。
  3. 所有帳號權限相同，可使用全部功能；請為每位警衛建立個人帳號，人工放行與手動開閘會記錄操作人。

左側選單：

選單 用途
即時監控 車道即時畫面、今日統計、最新進出、目前在場車輛
住戶白名單 戶別與住戶車輛管理
訪客管理 預約／現場登記訪客、追蹤在場與逾時
黑名單 禁止進入的車輛
進出紀錄 查詢歷史紀錄、檢視截圖、匯出
警示中心 黑名單、未登記車、訪客逾時、設備異常等警示
系統設定 車道硬體、辨識參數、操作員帳號

8. 即時監控

值班時的主畫面。

今日統計：今日進場、今日離場、目前在場車輛、在場／逾時訪客、今日拒絕、未處理警示。點「未處理警示」可直接跳到警示中心。

車道即時畫面：每個車道一張卡片，顯示即時影像與連線狀態。

  • 手動開閘：不經辨識直接開閘（例如救護車、無牌車）。會留下一筆類別為「手動開閘」的紀錄。
  • 手機鏡頭：顯示 QR Code，讓手機成為此車道的攝影機。
  • 畫面顯示「等待影像訊號」代表攝影機未連線。

最新進出紀錄：即時列出最新事件，有截圖的可點「檢視」看現場照與車牌特寫。

目前在場車輛：已進場、尚未離場的車輛。若車輛實際已離開但系統未記錄（例如離場時辨識失敗），按 手動結清離場。

測試辨識工具（選用）：到「系統設定 → 辨識與保留參數」開啟「在即時監控顯示測試辨識工具」後，車道卡片會多出：

  • 模擬辨識：輸入車牌（例 ABC-1234），模擬攝影機辨識到這台車。
  • 上傳圖片辨識：上傳車輛照片進行辨識。

此開關只對目前這台電腦的瀏覽器有效。注意：模擬與上傳辨識會照常判斷並觸發開閘、留下紀錄，正式值班時請關閉。

9. 處理未登記車輛（待確認視窗）

辨識到不在白名單、訪客名單、黑名單的車輛時，畫面會跳出 待確認｜未登記車輛 視窗，並播放提示音（可在系統設定關閉）。

視窗內容：現場截圖、車道、辨識到的車牌、車牌特寫、車種、時間、辨識信心。

9.1 先確認車牌是否辨識錯誤

若辨識結果與實際車牌不同，按 修正車牌，輸入正確車牌後按 比對。系統會重新比對名單並顯示結果（例如「住戶車輛」「黑名單」）。按 還原 可回到原辨識結果。

9.2 選擇處理方式

選項 適用情境 需填寫 確認按鈕
放行一次 快遞臨停、已電話向住戶確認 備註（選填） 確認放行並開閘
登記為訪客並放行 會停留一段時間的訪客 拜訪戶別、訪客姓名（必填）；電話、車種、授權時數（1／2／4／8／24 小時）、事由 建立訪客並開閘
拒絕進入 未聯繫住戶、可疑車輛 備註（選填，例：未事先聯繫住戶） 確認拒絕

選「登記為訪客」後，該車在授權時段內再次進出都會自動放行，離場時自動記為已離場。

9.3 多台車同時等待

視窗底部顯示 待處理佇列 N 筆。按 稍後處理 可先關閉視窗，之後到 進出紀錄 找到「待處理」的紀錄按 處理 重新開啟。

超過「待處理事件逾時」時間（預設 10 分鐘）仍未處理的事件，系統會自動結案為「拒絕」（通常代表車輛已倒車離開），並在備註寫明原因。

10. 住戶與車輛白名單

10.1 新增戶別

按右上 新增戶別，填寫：

  • 戶別（必填，例：A棟5F-2）
  • 住戶姓名、聯絡電話、備註

10.2 新增住戶車輛

在戶別列按 加車（或展開後按 + 新增車輛）：

欄位 說明
車牌號碼 必填，例 ABC-1234、123-XYZ。輸入時有無 - 皆可
車種 汽車／機車
有效起日／迄日 可不填。迄日不填代表永久有效；租客可填租約到期日
啟用 關閉後暫停此車的自動放行，資料保留
備註 例：第二台車、租客

只有「啟用」且在有效期內的車輛會自動放行。

10.3 搜尋、編輯與刪除

  • 上方搜尋框可依戶別、住戶姓名、車牌搜尋。
  • 每台車與每個戶別都可 編輯、刪除。暫時不讓某台車進出，建議用「停用」而非刪除，以保留資料。

11. 訪客管理

11.1 登記方式

按鈕 用途
預約登記 住戶事先告知訪客來訪時間
現場登記 訪客已到現場

表單欄位：拜訪戶別（必填）、訪客姓名（必填）、聯絡電話、車牌號碼（步行訪客可留空）、車種、事由、授權時段（必填，起訖時間）。

有車牌的訪客在授權時段內抵達時，會被自動辨識並放行。

11.2 分頁

分頁 內容
今日訪客 今天的所有訪客
目前在場 已入場、尚未離場
逾時未離場 超過授權時段＋寬限時間仍在場
即將來訪 未來的預約
全部紀錄 所有訪客

11.3 操作

按鈕 出現時機 說明
標記入場 狀態為「已預約」 步行訪客或辨識失敗時手動標記
標記離場 狀態為「已入場」或「逾時未離場」 手動標記離開
編輯 隨時 修改資料、延長授權時段
取消 狀態為「已預約」 取消預約

11.4 逾時未離場

訪客超過授權結束時間＋寬限時間（預設 15 分鐘）仍未離場，系統每分鐘檢查一次，狀態會變成「逾時未離場」並在警示中心產生「訪客逾時」警示。處理方式：聯繫住戶確認，必要時 編輯 延長授權，或於訪客離開後 標記離場。

12. 黑名單管理

按 加入黑名單：

欄位 說明
車牌 必填
車種 不限／汽車／機車
原因 會顯示在警示內容中
生效中 關閉可暫停而不刪除

黑名單優先於所有名單：即使同一車牌也登記為住戶或訪客，仍會被拒絕並產生「黑名單警示」。

13. 進出紀錄查詢與匯出

13.1 查詢

篩選條件：日期區間、車牌關鍵字、車道、車種（汽車／機車／未知）、類別（住戶／訪客／黑名單／未登記／手動開閘）、結果（自動放行／人工放行／拒絕／待處理）。設定後按 查詢，按 重設 清除條件。每頁可顯示 20／50／100 筆。

列表欄位：截圖、時間、車道、方向、車牌、車種、類別、處理結果、戶別、辨識信心、操作人、備註。

  • 點截圖或 檢視 可放大現場照與車牌特寫。
  • 結果為「待處理」的紀錄可按 處理 重新開啟待確認視窗。

13.2 匯出

按右上 匯出，選 Excel（.xlsx） 或 CSV。匯出內容依目前的篩選條件。

截圖預設保存 90 天，超過會自動刪除；文字紀錄不會刪除。需要長期留存的截圖請自行另存。

14. 警示中心

警示類型 觸發時機
黑名單警示 辨識到生效中的黑名單車輛
未登記車輛 辨識到未登記車輛
訪客逾時 訪客超過授權時段＋寬限仍在場
攝影機離線 車道攝影機中斷
柵欄異常 開閘指令失敗
  • 上方可切換 未處理／已處理／全部，並顯示各類型數量。
  • 處理完畢後按 標記已處理，或按 全部標記已處理。
  • 待確認事件被處理或逾時結案時，對應的警示會一併標記為已處理。

15. 系統設定

15.1 車道與硬體

新增、設定、刪除車道，以及 測試開閘、📱 手機鏡頭。狀態欄顯示：連線中／離線／停用。詳見第 4 節。

15.2 辨識與保留參數

調整後按 儲存設定（即時生效），不需重新啟動。各參數說明見附錄 B。

15.3 操作員帳號

  • 新增操作員：帳號（英數字）、顯示名稱（例：早班警衛）、密碼（至少 6 碼）。
  • 停用／啟用：人員離職時請停用帳號。
  • 重設密碼：為忘記密碼的同仁設定新密碼。

附錄

A. 放行判斷規則

每次辨識到車牌，系統依下列順序判斷，命中即停止：

  1. 黑名單（生效中）→ 拒絕，發出黑名單警示
  2. 住戶車輛（啟用且在有效期內）→ 自動放行
  3. 訪客（未取消且在授權時段內）→ 自動放行 - 離場車道另外放行「已入場」或「逾時未離場」的訪客，即使授權時段已過
  4. 近似車牌修正：前三項都未命中時，若車牌與某一台住戶／訪客車牌只差 1 個容易誤讀的字元（例如 8↔B、0↔D、5↔S），且候選只有一台、也不與黑名單相近，則視為該車並自動放行。紀錄會註明「近似修正自 ○○○」
  5. 車道設定「未知車自動放行」 → 自動放行
  6. 以上皆否 → 待處理，跳出待確認視窗

另外，同一車道同一車牌在「去重秒數」內（預設 30 秒）只會記錄一次，避免車輛停在攝影機前重複觸發。

D. 常見問題排解

Q：手機掃 QR Code 後無法開啟相機？ 手機瀏覽器只允許 HTTPS 網頁使用相機。請確認伺服器以 --ssl 啟動，且手機與伺服器在同一網路；看到憑證警告時選「進階 → 繼續前往」，並允許相機權限。

Q：第一次辨識很慢？ 首次辨識會下載並載入辨識模型（約數十 MB），完成後即可離線運作。

Q：車道顯示「離線」？ 檢查攝影機電源與網路、攝影機來源網址是否正確（可用 VLC 開啟同一個 RTSP 網址測試）。離線時警示中心會出現「攝影機離線」。

Q：按開閘柵欄沒動作？ 在系統設定按「測試開閘」，並到警示中心查看「柵欄異常」的錯誤訊息。常見原因：繼電器 IP 改變、url 填錯、伺服器與繼電器不在同一網段、Modbus 未安裝 --extra modbus。

Q：住戶車輛沒有自動放行？ 到住戶白名單確認該車為「啟用」、今天在有效期內，且車牌輸入正確。也可到進出紀錄查看系統實際辨識到的車牌與信心值。

Q：忘記密碼？ 請其他同仁在「系統設定 → 操作員帳號」按「重設密碼」；若無人能登入，由 IT 在伺服器執行 uv run gate reset-password <帳號>。

Q：雲端版每次重啟後都被登出？ 未設定 GATE_SECRET_KEY，每次重啟會產生新的金鑰。請設定一組固定的隨機字串。
